## Data model (Supabase — schema is manual, `supabase/schema.sql`)
- `formats(code PK, name, last_updated_at)` — codes ST/PI/MO/PAU/PREM. `last_updated_at` is the **per-format freshness source of truth**: the scraper stamps it after a successful run and the frontend reads it for the "Updated X ago" indicator.
- `archetypes(id, format_code FK, name, color_identity, signature_card_name, art_image_url, art_crop_url, unique(format_code,name))` — one per format; the scraper upserts (get-or-create), never deletes per-run. `signature_card_name`/`art_image_url`/`art_crop_url` (nullable) are the archetype's most-played non-land card + its hotlinked Scryfall images, recomputed each run. A functional `unique(format_code, lower(name))` index additionally blocks case-variant duplicates.
- **No `metagame_snapshots` / `format_window_freshness` tables** — dropped in `derive-metagame-from-decks`. The metagame breakdown is **derived at read time** from the decks (grouped by archetype within the window's date range); freshness is per-format via `formats.last_updated_at`.
- `events(id, source_event_id, format_code FK, name, event_date, player_count, unique(source_event_id, format_code))` — a MTGTop8 event. `player_count` (nullable) is the tournament size, parsed from the event page when MTGTop8 reports it (else null); it weights the performance Power Score.
- `decks(id, event_id FK, archetype_id FK, source_deck_id, player, placement, unique(event_id, source_deck_id))` — one deck at an event. `placement` is raw text ("1", "3-4", "5-8") because `placing` is a reserved SQL word.
- `deck_cards(id, deck_id FK, board 'main'|'side', quantity, card_name, scryfall_name, set_code, collector_number, image_url)` — one card line; `scryfall_*` + `image_url` are **populated** by the Scryfall mapping (scrape-time + one-time backfill); still nullable, and a resolution miss (e.g. silver-border cards) stays null → export falls back to `card_name`, art to the placeholder. `image_url` is the backfill's completeness sentinel.
- RLS: anon SELECT only on all tables; writes only via service-role key.

## Gotchas learned (save time)
- **Time windows are format-independent LOGICAL keys** (`5days`/`2weeks`), NOT raw MTGTop8 params. The frontend applies them as **client-side date filters** over the decks (and derives the breakdown from those decks); there is **no `meta_window` column** anymore (dropped with the snapshot tables in `derive-metagame-from-decks`). **MTGTop8's numeric `meta` IDs are per-format** — same window, different ID per format — so the scraper still maps `(format, window) → meta ID` via `WINDOW_META`/`meta_id_for` in `scraper/mtgtop8.py`. Hardcoding one format's IDs for all formats silently stores identical data (the bug that time-frame verification caught). The decklist pass gathers only `2weeks` (superset of `5days`) and follows all events-list pages (`&cp=N`). "2 Months"/"Large Events"/"MTGO" are not tracked.
- **`window` and `placing` are reserved SQL keywords** — that's why the live `decks.placement` column isn't named `placing` (and why the dropped `meta_window` wasn't `window`); quoting an identifier is a cross-stack footgun.
- **Global CSS only applies if imported in `src/main.tsx`.** `src/index.css` is orphaned Vite-template leftover and does nothing — layout classes live in `src/styles/dashboard.css` (imported by main.tsx). A class-based layout that "does nothing" is almost always this.
- **Schema deploy dance:** applying `supabase/schema.sql` needs the **service-role key** (a human/CI step; the assistant only has the anon key). After merging a schema+scraper PR: apply the schema in the Supabase SQL editor, then `gh workflow run scrape.yml --ref main` to repopulate. `schema.sql` is idempotent (safe to re-run); validate SQL locally with **`pglast`** (the real PostgreSQL parser — it DOES catch reserved-keyword-as-identifier errors, unlike `sqlglot`).
- **Printing selection prefers the PLAIN treatment.** `scraper/scryfall.py` picks one printing per card by `_selection_key = (plain, set_type_tier, released_at, set_code)` — plain treatment (not promo/crossover/`full_art`/`textless`/`borderless`/showcase/extended/inverted) beats set-type tier (`expansion`/`core`/`masters` > neutral > `commander`/`draft_innovation`) beats recency. Only `border_color == "borderless"` demotes — black/white/silver/gold borders are fine. **Any change to this heuristic needs a `--remap-scryfall` run** to reach existing rows.
- **Color identity is name-first, cards-fallback** (as of `derive-color-identity-from-cards`). Primary signal is the archetype **name** (guild/shard/mono/explicit letters) via `scraper/mtgtop8.py:color_identity_for` — MTGTop8 exposes no mana symbols. When the name yields **nothing**, the identity is **derived from the decks' cards' Scryfall `color_identity`** (`color_identity_from_decks`, kept if a color is in ≥ `COLOR_IDENTITY_MIN_DECK_SHARE`=0.35 of the archetype's decks) by `SupabaseWriter.refresh_archetype_color_identity`, recomputed each run (idempotent, change-detected PATCH). Needs decks to derive — an archetype with **no decks in the window stays gray**. Any tuning of the share constant / a min-deck floor only touches `mtgtop8.py`; re-run the one-time `--refresh-color-identity` (Actions `format=refresh-color-identity`) to reach existing rows.
- **Power Score = performance; its Tier badge is 2-week-anchored (stable) and tournament-size-weighted.** `src/lib/powerScore.ts` scores an archetype from deck **placements** (bracket finish-quality → **size-weighted** **Wilson lower bound of the *mean* quality** → **Fisher–Jenks** tiers). Each finish is weighted by its event's **`player_count`** via `sizeWeight` (clamped `[SIZE_WEIGHT_MIN 0.35, SIZE_WEIGHT_MAX 2.5]` around `SIZE_REF 64`; a **null/unknown size → the 0.35 small-event floor**, never dropped), and the score uses **Σ weights as the effective Wilson `n`** (bigger/more events ⇒ less shrink). A **`T1_MIN_DECKS`=3 floor** bars an archetype with too few supporting decks from Tier 1 (it drops to **T2**, not the fringe) so single-tiny-event winners don't flood T1. `archetypePowerScore(placements, sizes?, z)` — omitting `sizes` gives neutral weight 1 (pure unit tests); production passes a per-finish sizes array parallel to placements (`useMetagame` builds `twoWeekSizes` alongside `twoWeekPlacements`). The badge always uses the **2-week** score against the 2-week Jenks field, so toggling `5days`⇄`2weeks` never changes it; the recent-window signal is the separate **▲/▼/– trend arrow** (`TrendIndicator`, only on Last 5 Days). The trend compares **raw mean quality** between windows — **NOT** the Wilson-shrunken score, and stays **UNWEIGHTED** by size (`windowTrend` takes placements only), so it reflects a real performance change, not which tournaments were in the window. `useMetagame` fetches the **2-week corpus once** and date-filters client-side. Calibration constants (`Z_DEFAULT`=2.0, `SIZE_REF`/`SIZE_WEIGHT_MIN`/`SIZE_WEIGHT_MAX`, `T1_MIN_DECKS`, `TREND_EPS` 0.02, `MIN_TREND_DECKS` 3) sit at the top of `powerScore.ts`; property tests don't depend on exact values. Share % is untouched. **Note:** existing events have `player_count` = null until a re-scrape backfills sizes (the incremental scraper skips already-stored events), so weighting is uniform (all-small) until then — the tier improvement so far is from the `Z`/floor change; sizes refine T1 further once populated.
- **Tests:** jsdom has no `matchMedia` — it's stubbed in `src/test/setup.ts` (the sidebar drawer needs it). Scraper tests use saved fixtures under `scraper/tests/fixtures`, never live network.
- Transient CI `npm ECONNRESET` happens occasionally → `gh run rerun <id> --failed`.
- `.env.local` holds `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` (set locally and in Vercel) — useful for read-only anon verification via `curl` against the PostgREST API.
